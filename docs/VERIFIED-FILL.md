# Verified fill boundary

The public preparation API binds immutable exact template/profile bytes, validates supplied data, assigns every target (including blanks and checkbox Off), generates complete normal appearances, closes and reopens the result, and verifies values, geometry, resources and generated paint. Flattening uses those verified normal appearances and reopens again to check that interactive fields/widgets are absent and expected paint is retained. Create-new publication verifies closed artifact bytes before commit.

Form 941 uses its existing embedded font and the reviewed eight `MMddyyyy` date cells. Schedule B embeds the exact bundled Liberation Serif Regular program at fixed 10 pt and admits printable ASCII plus É subject to glyph and fit checks. Its original source-font admission remains separate from the explicit replacement policy. Filling emits `W_FONT_EXPLICIT_REPLACEMENT`; unsupported Unicode, unexpected font resources/defaults and text that does not fit are rejected. There is no automatic fallback or shrink-to-fit.

The generated AcroForm, field and widget defaults and populated appearances must reference the verified embedded font. Closed-readback checks cover the exact font program, metrics and appearances; flattened output must retain the expected paint and embedded font resources. The earlier native-font visual failure remains historical. The corrected cut passed the selected two-viewer visual review described in [development status](DEVELOPMENT-STATUS.md); that is not universal viewer, editing, print or filing acceptance.

Checkboxes use reviewed resource-free vector marks rather than a viewer-substituted mark font. Unsupported clipping, opacity, transformations, unknown paint operators and unexpected active content fail the bounded verifier.

Publication status and filing status are separate. A create-new artifact may be committed before diagnostic output fails. Preserve and inspect the caller-requested destination on an uncertain result. Force replacement and whole-job output remain disabled.

## Configured AcroForms in the generic draft

The generic path adds an immutable `FormConfigurationSnapshot` preparation overload. Supported policy is `configured-acroform-v1` with `none-v1` normalization: it does not perform the built-in IRS cleanup on arbitrary PDFs. Each configured field binds the observed resource, geometry, size and declared layout. Text uses either a supported preserved embedded TrueType/WinAnsi source or the explicit bundled Liberation Serif ASCII-plus-É strategy; checkbox policies are bounded vector marks. Unsupported active content, signatures, XFA, field types or malformed resources remain refusals.

Closed-readback checks include serialized field/widget default appearance and font resources even for blank fields, plus policy-specific AcroForm checks, populated appearance paint and fixed geometry. The preserved-font strategy intentionally leaves shared AcroForm defaults unchanged; its explicit field/widget resources select the admitted fonts. Both editable and flattened output retain the same create-new verification boundary. The canonical raw field/widget inventory is bounded and cross-checked by exact ownership and wrapper identity, including inherited field types and unnamed widgets with local defaults. The combined synthetic Linux regression checkpoint has passed as described in [development status](DEVELOPMENT-STATUS.md); a separate unchanged-engine synthetic third-form workflow and its selected Linux structural/raster review have also passed. This does not establish interactive viewer editing/reset, Windows, physical-print or arbitrary-form acceptance. See [configuration workflow](GENERIC-ONBOARDING.md).
